El flujo completo: instalación desde cero → configuración → uso → desinstalación

Antes de empezar

Dos cosas revisadas a mano, una vez:

0.1 · Que PostgreSQL esté instalado (motor de la base)
Ya lo tenés instalado y NO se tocó. Lo usamos así, sin cambiar nada.
0.2 · Que el proyecto esté ahí
/home/stward/Proyectos/taller-equipos
Es el único lugar que entra en juego desde acá. Todo lo demás se boró.
Importante: tu copia con los 568 registros está a salvo fuera de la máquina, en ~/respaldos-taller/migracion-20261102-0944/. Si querés recuperar esos datos más adelante, el paso 4.4 lo explica.
1

Crear la base por primera vez

Una sola vez. Cinco comandos, copiados tal cual.

1.1 · Encender el motor (si está detenido)
cd ~/Proyectos/taller-equipos scripts/bd.sh start
Espera hasta que el motor acepte conexiones. Este comando es la única forma de arrancar PostgreSQL en esta máquina: no es un servicio del sistema.
1.2 · Crear el dueño de la base (rol de aplicación)
psql -X -d postgres -c "CREATE ROLE taller_app LOGIN PASSWORD 'poné-tu-clave';"
Es el usuario con el que la aplicación va a hablar con la base. Nunca uses el superusuario postgres en la app.
1.3 · Crear la base
psql -X -d postgres -c "CREATE DATABASE taller_dev OWNER taller_app;"
↓
1.4 · Probar la conexión
psql -X -d "postgresql://taller_app:poné-tu-clave@localhost:5432/taller_dev" -c "select 1;"
Si dice 1, la base está lista.
2

Armar el instalador y ejecutarlo

Del proyecto a una copia instalada, con el asistente.

2.1 · Armar el paquete (una vez por versión)
cd ~/Proyectos/taller-equipos scripts/empaquetar.sh
Deja dist/taller-equipos/ (≈ 250 MB). Tarda un minuto y deja el ejecutable listo sin Python instalado.
↓
2.2 · Abrir el wizard de instalación
dist/taller-equipos/taller-equipos --instalar
Se abre una ventana con dos opciones: Solo para mí (sin clave) o Para todos los usuarios. Casi siempre elige la primera.
↓
2.3 · Clic en «Instalar»
Copia el programa a ~/.local/lib/taller-equipos, crea el lanzador ~/.local/bin/taller-equipos y deja la entrada en el menú de aplicaciones. Sos libre de cerrar la ventana cuando termine.
Otro camino equivalente: hacé doble clic en el menú → «Taller de equipos · Instalar». Es el mismo wizard, sin terminal.
3

Configurar (única vez)

Marca de la institución, conexión, base — automatico.

3.1 · Abrir el programa
~/.local/bin/taller-equipos
Como todavía no está configurado, se abre solo: «Puesta en marcha».
↓
3.2 · Identidad (1 · Identidad)
Nombre visible de la app, organización y logo. Esto queda guardado solo en tu usuario y no se toca al reinstalar.
↓
3.3 · Conexión (2 · Conexión a la base de datos)
Servidor: localhost · Usuario: taller_app · la contraseña que vos elegiste · Base: taller_dev. Después: Probar conexión.
↓
3.4 · Guardar y continuar
Con la casilla «Copiar este programa a una carpeta propia» marcada, el propio asistente deja todo instalado y configurado de una sola vez. Las tablas se crean solas dentro de la base (13 tablas + la vista de estados).
Nota: si preferís toda la configuración de la base ajena al asistente gráfico, se puede escribir .env a mano en la raíz del proyecto. Pero el asistente lo hace todo y evita errores.

4.4

Recuperar tus 568 registros (opcional)

pg_restore --no-owner --no-privileges \\ -d "postgresql://taller_app:poné-tu-clave@localhost:5432/taller_dev" \\ ~/respaldos-taller/migracion-20261102-0944/taller_dev.dump
Trae todo: movimientos, áreas, técnicos, el historial completo. Guía del paquete: LEEME-MIGRACION.md dentro del respaldo.
5

Desinstalar

5.1 · Con el wizard (recomendado)
~/.local/bin/taller-equipos --desinstalar
También está en el menú: «Taller de equipos · Quitar». Dice exactamente qué borra y qué no. La base de datos nunca se toca.
5.2 · Borrar la base (separado, es tu decisión)
psql -X -d postgres -c "DROP DATABASE taller_dev;" psql -X -d postgres -c "DROP ROLE taller_app;"
Solo si de verdad querés empezar de cero de nuevo. Está fuera del desinstalador por eso mismo.
